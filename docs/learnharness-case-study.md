# 🔬 Разбор LearnHarness: как устроен настоящий агентный харнес

[← назад к курсу](../README.md)

[LearnHarness](https://github.com/amosblomqvist/learnharness) — open-source приложение (Next.js + Electron, TypeScript, лицензия AGPL-3.0), в котором AI-агенты проводят уроки: выясняют, где кончается твоё понимание, строят план до цели, учат шаг за шагом и копят знания в постоянном графе. Ниже — разбор его архитектуры по документации проекта ([architecture.md](https://github.com/amosblomqvist/learnharness/blob/main/docs/architecture.md), [compaction-accounting.md](https://github.com/amosblomqvist/learnharness/blob/main/docs/compaction-accounting.md), [teaching-methodology.md](https://github.com/amosblomqvist/learnharness/blob/main/docs/teaching-methodology.md)) с переводом на язык нашего курса.

> Разбор описывает состояние репозитория на октябрь 2026. Проект активно развивается — сверяйся с оригиналом.

---

## 1. Что делает продукт

1. **Замер.** До обучения агент выясняет, где кончается понимание по каждой части, на которую опирается тема. Важны не только ответы, но и уверенность и рассуждение ученика.
2. **План.** Строится карта зависимостей от стартовой точки до цели. План виден ученику.
3. **Обучение.** Каждый шаг опирается на уже понятое: предсказание → объяснение → проверка. Заблуждения чинятся до того, как на них что-то строится.
4. **Практика.** Отдельные сессии с разнообразными задачами, в которых нужное знание должно «всплыть» само.
5. **Граф знаний.** Выученное накапливается как утверждения и цепочки рассуждений, переживает сессии.

Ключи — свои (BYOK, 30+ провайдеров), данные — локально, промпты видимы и редактируемы.

## 2. Главный закон архитектуры

> **Импорты направлены внутрь, записи — в append-only журналы доказательств, всё остальное — вычисляется.**

Из этого закона следует почти всё остальное:

- **Чистое ядро** (`src/core`) — доменная логика без ввода-вывода: контракты, план, вопросы, фазы, граф, стоимость.
- **Всё внешнее** (файлы, LLM, браузер, ОС) — за **адаптерами** на краю.
- **Две точки сборки** (composition roots): `stores.ts` — хранилища, `chat-handler.ts` — один ход разговора. Только они соединяют адаптеры с ядром.
- **Правила импортов проверяет линтер** (`import/no-restricted-paths`): UI может импортировать только ядро; ядро не импортирует ничего ниже себя; агентный слой получает зависимости через фабрики, а не импортом.

```
SHELL   app/, components/   — HTTP-маршруты и UI, без доменной логики
SERVER  src/server          — точки сборки и именованные «швы», ноль бизнес-логики
AGENT   src/agent           — циклы агентов, инструменты, фрагменты промптов, субагенты
CORE    src/core            — чистый домен, без IO
STORE   src/store           — адаптеры файловой системы, единственные, кто пишет в data/
```

**Урок для нас:** харнес быстро обрастает логикой. Если с первого дня отделить «что решаем» (ядро) от «как общаемся с миром» (адаптеры), его можно тестировать без сети и менять провайдеров, не трогая логику. В нашем курсе это видно в малом: `loop.py` не знает, какой провайдер внутри `LLM`, а тесты подменяют его на `ScriptedLLM`.

## 3. Шесть систем и правило «один писатель»

| Система | Единственный писатель для | Роль |
|---|---|---|
| **Classroom** — движок сессии | `data/chats/*.json` | ход разговора, замерщик → учитель, план, вопросы, фазы |
| **Workbench** — фоновая работа | `data/jobs/*.json` | запуск задач, субагенты: исследователь, демо, визуализации |
| **Library** — модель мира | `data/graph/*` журналы | конвейер извлечения — единственный писатель графа |
| **Practice** — наборы задач | `data/practice/*.json` | разбивка → генерация задачи → оценка ответа |
| **Stage** — оболочка UI | ничего на сервере | только читает через `/api/*` |
| **Machine room** — хост | процесс и конфиг | Electron, сервер Next, ключи |

Системы общаются только через **именованные идемпотентные протоколы**. Ни одна не пишет в чужое хранилище.

**Урок для нас:** гонки и «кто испортил файл» исчезают, когда у каждого хранилища ровно один писатель. В курсе так устроены `Ledger` и `FactMemory`: добавлять факты может только `FactMemory`, а состояние вычисляется из журнала.

## 4. Один ход разговора

Обработчик хода — чистая функция `Request → Response` с подменяемым построителем агента (для тестов). Порядок шагов:

1. **Замок хода** на чат. Если ход уже идёт — `409`, клиент подождёт и повторит.
2. **Забрать steer-сообщения** из очереди (результаты фоновых задач).
3. **Write-ahead:** сохранить сообщения *до* запуска модели.
4. **Собрать агента из записи сессии.** Если в транскрипте уже есть `probe_done` — это учитель, иначе — замерщик. История перестраивается заново каждый ход (stateless), висящие вызовы инструментов получают синтетический результат `INTERRUPTED`.
5. **Стрим** ответа в браузер.
6. **Client-side вопросы** (`quiz`, `ask_user_question`) не выполняются сервером: вызов уходит в браузер, ученик отвечает, **клиент проверяет ответ кодом** и возвращает результат — это запускает продолжение. Висящий квиз в записи сессии означает, что продолжить урок посреди вопроса можно «бесплатно».
7. **После хода:** каноническое сохранение, учёт usage, запуск извлечения знаний, если накопилось достаточно непокрытых токенов, и **всегда последним** — снятие замка.

**В курсе:** write-ahead — `SessionStore`; `INTERRUPTED` — `repair_dangling_tool_calls`; client-side инструменты — `Tool(client_side=True)` + `client_handler`; передача хода от замерщика учителю — `terminates=True` в `mini_tutor.py`.

## 5. Два агента и план

- **Замерщик (prober)** находит «пол» и «потолок» понимания квизами и уточняет цель вопросом. Вызов `probe_done` сохраняет оценку и передаёт ход учителю. Фазы идут строго: probe → plan → teach.
- **Учитель (teacher)** **один раз** создаёт план инструментом `plan_init`: граф в подмножестве mermaid, детерминированно разбираемый, с ошибками по номерам строк и проверкой на ацикличность (DAG).
- **План неизменяем.** Прогресс не записывается — статусы узлов (текущий / пройден / впереди) **вычисляются** из помеченных квизов в транскрипте.

**В курсе:** `plan_init` в `mini_tutor.py` проверяет граф топологической сортировкой и отказывает при цикле; `plan_status()` выводит прогресс из `quiz_log`, а не хранит его.

## 6. Фоновые субагенты: ack-and-steer

- Инструменты `research`, `demo`, `visual` **отвечают сразу** («принято»), учитель продолжает урок.
- Субагент работает в фоне. Результат превращается в **steer-сообщение** — user-сообщение с текстом для модели и полным артефактом для UI.
- **Конвейер пробуждения:** очередь на чат; когда ход свободен и нет висящего вопроса — запускается новый ход через тот же обработчик. При `409` — backoff 500 → 1000 → 2000 → 5000 мс.
- **Exactly-once:** детерминированные id (`steer_<jobId>`), проверка «уже доставлено» в каждой точке, статус задачи меняется только после сохранения хода. Зависшие задачи (> 15 мин) восстанавливаются после падения.
- Субагенты **проверяют, а не выдают с первого раза**: демо запускается в headless-браузере, SVG рендерится и осматривается моделью с поддержкой изображений.

**В курсе:** `harness/jobs.py` и `examples/05_subagents.py`.

## 7. Граф знаний: один писатель, два канала

- **Конвейер извлечения — единственный писатель графа.** Запускается, когда непокрытых токенов в сессии больше порога; работает строго последовательно в рамках одного источника.
- **Извлекатель** видит *только прозу учителя* (без сообщений ученика, рассуждений, вызовов инструментов) и выдаёт утверждения + **цепочки рассуждений** (посылки → вывод).
- **Аудитор** никогда не видит исходный текст — только найденные утверждения, и исследует существующий граф инструментами, решая только вопрос идентичности: связать с существующим или создать новое.
- **Слияние** — детерминированный код (не LLM): дедупликация цепочек, упрощение избыточных цепочек, контрольная точка покрытия.
- **Ошибка на любом этапе — ничего не записывается**, следующий запуск повторит.
- Чтение графа — чистое вычисление; главная страница никогда не вызывает запись.
- Учитель **не получает граф в промпт** — он сам исследует его read-only инструментами `list_sessions` / `list_propositions`.

**Урок для нас:** разделение доверия. LLM-этапы делают то, в чём сильны (понять текст, сравнить смыслы), а всё, что можно сделать детерминированно (запись, дедупликация, проверка структуры), делает код.

## 8. Компакция и учёт токенов

- Логика выбора границы портирована из `pi-coding-agent`: идём с конца до бюджета хвоста ~20 000 токенов, выбираем ближайшую допустимую границу user/assistant, **никогда не начинаем с результата инструмента**; если хвост — одни результаты, сохраняем и их вызов.
- Оценка размера — «символы / 4», изображения — фиксированная оценка.
- Сводка — свой «образовательный» промпт с сохранением непрерывности плана.
- **Счётчик контекста** берёт реальный usage последнего завершённого ответа; после компакции показывает `? / максимум`, пока не придёт новый замер. Стоимость сводок в счётчик контекста не попадает.

**В курсе:** `select_cutoff` и `compact` в `harness/context.py`.

## 9. Тестирование

- `npm test` — **детерминированно, без LLM, без сети**.
- Обработчик хода принимает подменяемый построитель агента — тесты гоняют его со **сценарными движками**.
- Порты хранилищ подменяются in-memory реализациями.
- Для компакции — «золотые» фикстуры, сверяющие поведение с оригиналом.

**В курсе:** `tests/test_harness.py`, `ScriptedLLM`, фейковый OpenAI-совместимый HTTP-сервер.

## 10. Что взять в свой харнес

1. **Агент собирается из записи сессии каждый ход.** Никакого скрытого состояния в памяти процесса → падение не страшно.
2. **Write-ahead + синтетический INTERRUPTED** — сессия переживает любой сбой.
3. **Проверяемое — кодом, понимаемое — моделью.** Ответы на квизы, план-DAG, слияние графа — детерминированный код.
4. **Один писатель на хранилище, append-only журналы, состояние — вычисляется.**
5. **Фоновая работа через ack-and-steer с exactly-once.**
6. **Промпты — фрагментами в файлах**, видимые пользователю.
7. **Архитектурные правила — в линтере**, а не в README.
8. **Тесты без сети** на каждый коммит.

## Как самому пройтись по коду LearnHarness

```bash
git clone https://github.com/amosblomqvist/learnharness.git && cd learnharness
ls src/agent/prompts/*            # фрагменты промптов: shared / prober / teacher / practice
less docs/architecture.md         # канонический документ архитектуры
less docs/teaching-methodology.md # методика обучения
npm install && npm test           # детерминированные тесты
```

- [ ] Почему квиз проверяется в браузере, а не моделью?
- [ ] Что произойдёт, если процесс упадёт посреди извлечения знаний?
- [ ] Почему аудитор не видит исходный текст сессии?
- [ ] Как обеспечивается, что результат фоновой задачи не придёт дважды?
