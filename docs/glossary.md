# 📖 Глоссарий RU ↔ EN

[← назад к курсу](../README.md)

Документация и статьи по агентам почти все на английском. Эти термины помогут искать и читать.

## Модели и API

| Русский | English | Пояснение |
|---|---|---|
| большая языковая модель | large language model (LLM) | модель, предсказывающая следующий токен |
| токен | token | кусок текста, единица счёта и оплаты |
| токенизатор | tokenizer | режет текст на токены |
| контекстное окно | context window | максимум токенов на входе + выходе |
| системный промпт | system prompt | инструкции с наивысшим приоритетом |
| сообщение / роль | message / role | `system`, `user`, `assistant`, `tool` |
| температура | temperature | случайность выбора токенов |
| стриминг | streaming | ответ кусками по мере генерации |
| события, отправляемые сервером | Server-Sent Events (SSE) | протокол стриминга по HTTP |
| причина остановки | stop reason / finish reason | почему модель закончила ответ |
| использование | usage | счётчики токенов в ответе |
| кэширование промптов | prompt caching | дешёвый повтор одинакового префикса |
| размышление / рассуждение | extended thinking / reasoning | скрытые шаги рассуждения модели перед ответом |
| свой ключ | bring your own key (BYOK) | пользователь платит провайдеру напрямую |
| эмбеддинг | embedding | вектор, отражающий смысл текста |
| ограничение частоты | rate limit | лимит запросов/токенов в минуту, ошибка 429 |
| экспоненциальная задержка | exponential backoff | повтор с растущей паузой |
| джиттер | jitter | случайная добавка к паузе, чтобы клиенты не били синхронно |

## Агенты и харнес

| Русский | English | Пояснение |
|---|---|---|
| харнес, обвязка | harness | всё вокруг модели: цикл, инструменты, контекст, память, UI |
| агентный цикл | agent loop | вызывать модель, пока она просит инструменты |
| агент | agent | модель, сама выбирающая шаги в цикле с инструментами |
| воркфлоу | workflow | цепочка шагов, заданная кодом |
| инструмент | tool | функция, которую модель может попросить вызвать |
| вызов инструмента | tool call / tool use / function calling | запрос модели на выполнение функции |
| результат инструмента | tool result | что вернул инструмент, уходит обратно в модель |
| схема | JSON Schema | описание аргументов инструмента |
| параллельные вызовы | parallel tool calls | несколько инструментов за один шаг |
| траектория | trajectory / trace | последовательность шагов и вызовов агента |
| шаг / ход | step / turn | один вызов модели / одна реплика пользователя и ответ |
| субагент | subagent | агент, запускаемый другим агентом с чистым контекстом |
| оркестратор | orchestrator | агент, раздающий задачи субагентам |
| передача хода | handoff | один агент передаёт разговор другому |
| фоновая задача | background job | работа, идущая параллельно разговору |
| «принял — подтолкну» | ack-and-steer | мгновенный ответ инструмента + результат позже сообщением |
| ровно один раз | exactly-once | доставка без потерь и дублей |
| идемпотентность | idempotency | повтор операции не меняет результат |
| человек в цикле | human-in-the-loop (HITL) | подтверждения и вопросы человеку |
| клиентский инструмент | client-side tool | выполняется UI или человеком, а не сервером |
| ReAct | ReAct (reason + act) | паттерн «подумай → действуй → наблюдай» |
| протокол контекста модели | Model Context Protocol (MCP) | стандарт подключения инструментов и данных |

## Контекст и память

| Русский | English | Пояснение |
|---|---|---|
| контекст-инжиниринг | context engineering | управление тем, что модель видит |
| компакция, сжатие | compaction | замена старой истории сводкой |
| граница компакции | cutoff | с какого сообщения начинается сохраняемый хвост |
| сводка | summary | сжатое содержание отброшенной части |
| «гниение» контекста | context rot | падение качества при засорённом длинном контексте |
| висящий вызов | dangling tool call | вызов без результата после сбоя |
| память | memory | данные, переживающие вызов/сессию |
| долговременная память | long-term memory | факты между сессиями |
| транскрипт | transcript | полная запись сессии |
| запись до действия | write-ahead | сохранить до вызова модели |
| журнал только для дописывания | append-only log / ledger | изменения только добавлением |
| JSON Lines | JSONL | один JSON-объект на строку |
| генерация с поиском | retrieval-augmented generation (RAG) | подмешивание найденных документов в контекст |
| граф знаний | knowledge graph | утверждения и связи между ними |
| утверждение | proposition | атомарное утверждение в графе LearnHarness |
| цепочка рассуждений | reasoning chain | посылки → вывод |

## Качество и безопасность

| Русский | English | Пояснение |
|---|---|---|
| оценка, эвалы | evals | проверка поведения агента на наборе кейсов |
| модель-судья | LLM-as-a-judge | оценка ответа другой моделью по рубрике |
| эталонный набор | golden set / fixtures | кейсы с известным правильным результатом |
| бенчмарк | benchmark | стандартный набор задач для сравнения |
| наблюдаемость | observability | логи, трассы, метрики |
| трассировка | tracing | запись шагов с временем и стоимостью |
| внедрение промпта | prompt injection | инструкции, спрятанные в данных |
| взлом ограничений | jailbreak | обход правил модели |
| утечка данных | data exfiltration | вывод приватных данных наружу |
| «смертельная триада» | lethal trifecta | приватные данные + недоверенный ввод + канал наружу |
| песочница | sandbox | изолированная среда исполнения |
| принцип минимальных прав | least privilege | только необходимые инструменты и доступы |
| ограничители | guardrails | проверки входа/выхода и действий |

## Архитектура

| Русский | English | Пояснение |
|---|---|---|
| гексагональная архитектура | hexagonal architecture / ports and adapters | чистое ядро, внешнее — за адаптерами |
| порт | port | интерфейс, который ядро ожидает |
| адаптер | adapter | реализация порта для конкретной технологии |
| точка сборки | composition root | единственное место, где соединяются части |
| шов | seam | место, где поведение можно подменить (в тестах) |
| единственный писатель | single writer | одно хранилище — один компонент, который в него пишет |
| производное состояние | derived state | вычисляется из журнала, а не хранится |
| ориентированный ациклический граф | DAG (directed acyclic graph) | граф без циклов, например план зависимостей |
| топологическая сортировка | topological sort | порядок узлов DAG по зависимостям |
